# 세션 기록 — 학습지 사진 → 문제 생성 시도

이 문서는 코드 변경 사항이 아니라, 한 세션 동안 있었던 논의와 시행착오를 정리한 기록이다.
실제 앱(`public/quiz.html` 등)은 이 세션에서 건드리지 않았다 — 여기 정리된 건 별도로 만든
Artifact(단독 웹페이지) 실험에 대한 내용이다.

## 요청

기존 `/quiz.html`(Express 서버 + Claude API 키 필요)이 쓰기 번거롭다는 피드백에 따라, API 키나
배포 없이 **그 자리에서 바로 쓸 수 있는 페이지**를 만들어 달라는 요청이 있었다. 최종적으로는
"학습지 사진을 찍으면 Claude가 그 내용을 직접 분석해서 5지선다 문제를 만드는" 자기완결형
페이지를 원했다.

## 진행 경과

1. **Artifact(claude.ai 단독 페이지)로 제작.** Claude Artifact의 `sample` 런타임 기능
   (`window.claude.use('sample')`)을 이용해, 페이지 안에서 바로 Claude에게 문제 생성을
   요청하는 구조로 만들었다. API 키·서버 불필요.
2. **사진 선택 버튼이 안 눌리는 문제.** `<label for>` → JS 프록시 클릭 → 파일 인풋을 박스
   전체에 투명하게 덮는 방식까지 세 가지 방법을 시도한 끝에, 원인이 **인앱 브라우저(모바일
   앱 내장 웹뷰)** 였던 것으로 확인됐다. 실제 Chrome 브라우저로 열자 사진 선택 자체는
   정상 동작했다.
3. **사진을 Claude에게 직접 보내는 부분이 막힘.** `sample()`의 `images` 옵션으로 사진을
   보내자 `images_unavailable` 오류가 돌아왔다. 이는 페이지 코드 문제가 아니라, 이 세션
   (계정/뷰어)에서 아티팩트가 이미지를 Claude에게 보내는 기능 자체가 허용되어 있지 않다는
   뜻이다. 실제 사용자 테스트로 재현·확인됐다.
4. **대안으로 브라우저 내 OCR(Tesseract.js)을 시도**했으나, 사용자가 "사진 자체를 분석하는
   것"이 원래 목적이라며 텍스트 추출 방식을 원치 않는다고 명확히 함에 따라 되돌렸다.
5. **결론적으로 남은 선택지 두 가지**:
   - 다른 환경(특히 데스크톱 브라우저)에서 이미지 전송이 허용되는지 확인 — 사용자가 컴퓨터를
     쓸 수 없어 테스트하지 못함.
   - 사진을 이 대화(채팅)에 직접 올리면 Claude가 그 자리에서 분석해 문제를 만들고, 그 결과를
     페이지에 반영하는 방식 — 페이지 자체의 완전 자동화는 아니지만 "Claude가 사진을 직접
     본다"는 목적은 달성된다.

## 현재 상태

- Artifact 링크: `https://claude.ai/artifact/AMM5X98AvyrSzKCsEyqVde`
- 페이지 UI(진행판·5지선다·채점·오답 다시보기)는 완성되어 있고 정상 동작한다.
- **사진 → Claude 직접 분석 자동화는 사용자의 현재 뷰어 환경에서 플랫폼 제약으로 막혀 있다.**
  이 레포의 코드로 해결할 수 있는 부분이 아니다.
- 대화 후반부는 이 기술적 한계에 대한 반복적인 이견 조정으로 진행되었으며, 합의된 다음
  단계(채팅에 사진 직접 첨부, 또는 데스크톱 환경 테스트)는 아직 실행되지 않았다.
